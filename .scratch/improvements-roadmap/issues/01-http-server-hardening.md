# HTTP server hardening: timeouts + graceful shutdown + body limits

Status: ready-for-agent
Category: enhancement
Area: reliability

## What to build

Replace the bare `http.ListenAndServe` with a configured `*http.Server` that has
read/write/idle timeouts and a graceful shutdown path, and cap request body sizes on
JSON endpoints. Today one stalled query blocks the single SQLite connection, systemd
auto-restarts drop in-flight requests, and unbounded JSON bodies can OOM the process.

Covers plan items 1.1 and 1.2.

## Acceptance criteria

- [ ] `service/main.go` constructs `*http.Server{ReadHeaderTimeout, ReadTimeout, WriteTimeout, IdleTimeout}` instead of `http.ListenAndServe`
- [ ] `signal.Notify` + `server.Shutdown(ctx)` drains in-flight requests on SIGINT/SIGTERM
- [ ] `http.MaxBytesReader` (≈1 MB) applied to JSON `/api` request bodies; oversized bodies return 400/413
- [ ] Test asserts the server is constructed with timeouts; `Test*_RejectsOversizedBody` for the body cap
- [ ] `go test ./... -count=1` passes
- [ ] README/env documented if a timeout or body-size value is configurable
