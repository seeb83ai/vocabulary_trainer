# Split Store into focused sub-stores

Status: ready-for-agent
Category: enhancement
Area: backend-seam

## What to build

`Store` has 117+ methods; every handler depends on all of it. Introduce focused
sub-stores embedded by `Store` (no construction change) so handlers declare the narrowest
surface they use. Type-level reorganisation only — no SQL moves between files.

Covers plan item 5.7. Grouping was decided during planning (see below), so this is AFK.

## Grouping (decided)

| Sub-store | Methods |
|-----------|---------|
| `WordStore` | word CRUD, translation links, tag queries, `GetNextCard` |
| `QuizStore` | SM-2 progress, **confusion pairs, daily stats** |
| `MnemonicStore` | HMM actor/location/room/prop library, scene storage |
| `PinyinStore` | pinyin sound library + progress |
| `ComponentStore` | hanzi component progress + initialisation |
| `UserStore` | user CRUD, auth, password, settings |

## Acceptance criteria

- [ ] Sub-store types defined; `Store` embeds all of them (no change to `db.Open()` callers)
- [ ] Handler structs hold the narrowest sub-store they need (e.g. `QuizHandler` holds `QuizStore`, not `*db.Store`)
- [ ] No SQL moves between files — type-level only
- [ ] A new handler can be written depending only on `WordStore` without pulling in quiz/mnemonic methods
- [ ] `go test ./... -count=1` passes
